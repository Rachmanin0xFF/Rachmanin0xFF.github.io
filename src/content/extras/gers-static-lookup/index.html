    What a page shows

    The feature's name, type and key attributes, where it is on a map, its sources and licences, and how it changed between releases. Every page has a permanent link and a QR code.

    What's covered

    IDs in Overture's public GERS registry: buildings, places, transportation segments and connectors, and divisions (divisions, areas and boundaries). Base-theme features, building parts and addresses have IDs too, but they aren't in the registry, so they don't get pages here.

    Removed IDs

    Pages always show the latest release. IDs that have been removed keep a page that says when they left, and history comes from Overture's public GERS changelog.

    How this works

    This is a static copy of gers.page. There is no server: your browser reads Overture's parquet files straight from their public S3 bucket with HTTP range requests, using hyparquet.

    1. The STAC catalog names the latest release and lists each registry file's highest ID, which picks the one file that can hold yours.
    2. That file's page index narrows the search to a single page of about a megabyte.
    3. The registry row gives the release file and bounding box; the file's row-group bbox statistics narrow the read to one row group.
    4. The changelog shares the release's spatial partitioning, so history reads one file per release and change type.

    Looking up an ID without a browser

    This page is static: the same HTML for every ?id=. Feature details are fetched by JavaScript in the browser, so a plain HTTP fetch sees only this text. To look up a GERS ID yourself (for example, the id query parameter of this URL), run these three steps with DuckDB or any parquet reader. All reads are anonymous HTTPS against Overture's public bucket.

    1. Fetch https://stac.overturemaps.org/catalog.json. latest is the current release. registry.manifest is a list of [file, max_id] pairs sorted by ID; pick the first file whose max_id is greater than or equal to the ID.
    2. Read the registry row: 
      SELECT * FROM 'https://overturemaps-us-west-2.s3.us-west-2.amazonaws.com/registry/<file>' WHERE id = '<id>';
      No row means the ID isn't in GERS. A null path means the feature was removed after release last_seen.
    3. If path is set, read the feature from release last_seen. The bbox filter lets the reader skip all but one row group: 
      SELECT * FROM read_parquet('https://overturemaps-us-west-2.s3.us-west-2.amazonaws.com/release/<last_seen>/<path>')
WHERE id = '<id>' AND bbox.xmin = <bbox.xmin> AND bbox.ymin = <bbox.ymin>;

    History is in …/changelog/<release>/theme=<theme>/type=<type>/change_type=<added|data_changed|removed>/, partitioned the same way as the release, so the file with the same part-NNNNN number as path holds the ID's row. See the GERS registry docs.
